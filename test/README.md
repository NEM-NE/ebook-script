# 테스트 프로세스

이 레포는 두 계층의 E2E 테스트를 유지한다. 둘 다 실제 파이프라인
(`run-script.sh` → `screencapture.applescript` → `merge.sh`)을 그대로 돌린다.

| 테스트 | 대상 | 자동화 | 언제 |
|--------|------|--------|------|
| `test/smoke.sh` | Preview를 대역 리더로 사용 | 완전 자동 | 개발 중 / PR마다 |
| `test/real-e2e.sh` | 실제 교보 앱 | 반자동 (사람이 책을 열고 시각 확인) | 릴리스 전 / 캡처 로직 변경 시 |

## 사전 준비 (최초 1회)

터미널 앱(Terminal/iTerm2 등)에 두 권한을 부여한다:
- 시스템 설정 → 개인정보 보호 및 보안 → **접근성** — 페이지 넘김 키 입력에 필요
- 같은 화면 → **화면 기록** — 캡처에 필요

권한이 없으면 두 테스트 모두 명확한 안내 메시지와 함께 실패한다.

## test/smoke.sh — 자동 회귀 (자동 대역)

```bash
bash test/smoke.sh
```

번호가 크게 적힌 10페이지 테스트북을 자동 생성해 Preview로 열고, 캡처
영역을 Preview 창 좌표에서 자동 산출한 뒤 두 시나리오를 검증한다:

1. **전체 실행** — 10/10 페이지 캡처 → PDF 생성 → 임시 폴더 정리
2. **SIGINT 중단** — 중간에 중단 시그널 → 부분 PDF 병합 → 정리

교보 앱·책이 필요 없어 PR마다 돌릴 수 있는 기본 게이트다.
주의: 실행 중 약 60초간 키보드/마우스 금지 (실제 → 키 이벤트 발생).

## test/real-e2e.sh — 실앱 릴리스 게이트 (반자동)

```bash
bash test/real-e2e.sh                     # 기본: 3페이지, 마진 10px, 교보도서관
bash test/real-e2e.sh --pages 5 --margin 8 --app 2
```

흐름:
1. 가이드 프롬프트 — 교보 앱에서 책을 열고 Enter
2. 전경 뷰어 창 좌표에서 캡처 영역 자동 산출 (전경 프로세스 동적 인식)
3. 실제 파이프라인으로 N페이지 캡처 → 기계적 검증 (페이지 수·PDF·정리)
4. PDF 자동 오픈 → **사람이 시각 확인** (짤림·페이지 순서) → y/N로 삭제

`REAL_E2E_ASSUME_YES=1` 환경변수로 프롬프트 없이 실행(책이 이미 열려 있다고
가정, PDF는 보존) — 에이전트/자동화 실행용.

### 마진 참고

캡처 영역은 뷰어 창에서 `--margin`만큼 안쪽으로 줄인 사각형이다.
교보 뷰어는 콘텐츠가 창 가장자리까지 확장되므로 기본 10px. 짤리면 마진을
줄이거나, 페이지 전체가 창에 들어오도록 뷰어 줌을 조정한다.
(근본 해결은 로드맵의 자동 영역 인식.)

## 실패 시

- `cannot read the ... window` / 권한 안내 → 위 사전 준비 확인
- 캡처 0페이지 → 뷰어가 전경인지, 키 이벤트가 앱으로 가는지 확인
- PDF만 없음 → ImageMagick 설치 확인 (`brew install imagemagick`)
- 내용 짤림 → 마진/뷰어 줌 조정 (위 참고)
